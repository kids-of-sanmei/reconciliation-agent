# 第一块：数据接入与底稿准备

日期：2026-10-31。状态：已实现首版；本文保留目标约束，当前能力及操作方式见下方实现说明。

本块对应[整体流程](./00-整体流程.md)第 1—4 步，把后端接收到的文件变成可追溯、可计算、可逐行处理的数据，同时生成继承 A 表的 C 表底稿。

后续交给[第二块：逐行匹配与复核](./02-逐行匹配与复核.md)，最终文件由[第三块](./03-制表反向核查与交付.md)生成和验收。

## 1. 输入、输出和边界

输入为 A 表、B 表、对账年月，以及可选的字段映射、工作表范围、规格映射、日期容差和人工参考表。

输出为 `PreparedData`，包含任务上下文、已验证的结构映射、原始来源数据、标准化明细、C 底稿和 B 查询索引。

本块完成文件和数据准备，不作最终业务匹配，不把准备成功标记为对账完成。

## 2. 处理步骤

### 2.1 接收并保存输入

1. 为任务创建唯一 `task_id`，记录对账年月和输入角色。
2. 检查文件大小、类型、可读性及内容是否为空。
3. 原文件以独立文件标识保存，记录原文件名、内容摘要和接收时间。
4. 建立输入文件与后续产物清单，保留原文件，转换和加工写到新文件。
5. 缺少对账年月时可提出识别建议，确认后才能形成有效任务期间。

格式适配必须保留原始来源：`.xlsx` 直接读取工作簿；`.xls` 若经过转换，必须验证数据、公式和版式；CSV 没有 Excel 版式、合并和公式信息，需要明确相应输入模式。前端展示可上传的格式，必须与后端实际适配能力一致。

### 2.2 提取表结构与原始数据

程序读取：

- 工作表清单、名称和处理范围。
- 单元格原始值、数据类型、数字格式、公式及已有计算结果。
- 合并区域、隐藏行列、行高列宽、边框、对齐及填充信息。
- 表头候选、月份标题、明细区、空行、小计和合计行。

为来源位置分配稳定标识。原始行标识由文件、工作表和原始行号组成，后续 C 表插行不会改变它。内容完全相同的两条来源行也有不同标识。

输出结构摘要供识别使用；完整单元格和版式数据保存在程序侧。

### 2.3 识别字段和业务区域

已知模板由程序优先识别。陌生 A 表由模型根据表头、有限样例、合并信息和公式位置提出结构映射。

必须确定：

| 对象 | 必须明确的内容 |
| --- | --- |
| A 表 | 工作表范围、表头、明细区、日期、产品/规格、数量、单价、金额、合计位置；存在时保留票据号、单位及备注 |
| B 表 | 仓库、系统时间、单据号、货号、货名、规格、入库及出库数量/单价/金额；存在时保留固定成本价等附加字段 |
| 区域类型 | 业务明细、标题、表头、小计、合计、说明等，避免把合计当业务再处理 |

已知 B 模板的 E—J 为追溯字段，K—M 为入库字段，N—P 为出库字段。文档中的 `台州` 文件名前缀作为 B 表识别规则，同时必须验证表头；文件角色与结构冲突时进入待确认，不能仅凭列号继续处理。

模型输出是映射建议，程序检查列是否存在、数据类型是否合理、明细是否覆盖、合计是否被排除。存在多个业务工作表时分别保存映射，其他工作表完整保留；处理范围不明确时请求确认。

### 2.4 整理 A 明细并生成 C 底稿

1. 完整复制 A 工作簿生成独立 C 底稿，继承原始内容和基本版式。
2. 在业务处理范围解除影响明细处理的合并单元格，按原合并区域补全日期。
3. 不跨标题、分组或合计盲目向下填充；其他空字段也不能无条件继承上一行。
4. 解析日期，内部保存完整日期；支持文本日期、Excel 日期序列和工作簿日期基准。只有月日时使用已确认任务年份，遇到跨年歧义则保留待确认项。
5. 日期显示为实际业务月份的“月日”格式，月份标题随任务变化，不能固定“七月”。
6. 清除旧填充底色，保留边框、文字、对齐和其他必要样式，后续颜色交由对账状态控制。
7. A 明细按原始顺序形成列表，为每条记录保存原始行引用和底稿行引用。
8. 保存 A 原始业务数量、金额的逐行基准及重新计算的合计，供第三块独立验收。

日期补全等清理动作应有操作记录。原始值留在来源数据中，清理后的值只用于底稿展示和匹配。

### 2.5 整理 B 业务记录并建立索引

保留 B 表全部原始记录，解析系统时间并标记是否属于任务月份。反向核查的期间范围与匹配候选的搜索范围分开保存；跨月搜索只能按明确规则执行，不能把搜索窗口当成缺失统计月份。

索引维度至少包括方向、系统日期、单据号、货号、规格及数量。索引用于检索，不能改变或合并原始记录。

`b_row_id` 表示 B 原始行；`b_record_id` 表示该行的一个业务方向，例如 `B:file_b:sheet_1:25:in`。同一行同时存在入库和出库时分方向保存，零金额、零数量也保留；方向不明时保存 `unknown` 和问题原因，交后续复核或标注。

后续记录覆盖同时保留原始行数和按方向拆分的业务记录数，统计不得混用。没有被正确解析的 B 行必须形成问题记录，不能静默丢弃。

## 3. 程序与模型的分工

| 工作 | 程序 | 模型 |
| --- | --- | --- |
| 文件、公式、样式读取 | 执行并保留来源 | 按需读取摘要 |
| 已知模板适配 | 按规则识别 | 通常不调用 |
| 陌生字段映射 | 提供表头、样例并验证建议 | 提出语义映射及依据 |
| 日期、数字和合并处理 | 执行、校验和记录 | 帮助解释异常，不能猜造缺失值 |
| 规格别名 | 保存原始名及已确认映射 | 提出别名建议，不能默认为已确认规则 |
| C 底稿复制 | 执行 | 无需参与 |

## 4. 数据交接约定

以下是后续三个模块共同使用的基础约定。

### 4.1 任务上下文 `TaskContext`

| 字段 | 含义 |
| --- | --- |
| `schema_version`、`task_id` | 数据契约版本和任务标识 |
| `reconciliation_period` | 已明确的对账年月 |
| `files` | A/B/人工参考文件的角色、标识、位置及内容摘要 |
| `sheet_scope`、`field_mappings` | 处理工作表及验证后的字段映射 |
| `rule_version`、`rules` | 匹配规则版本、日期范围、名称映射等 |
| `data_version`、`stage` | 当前数据版本与处理阶段 |
| `confirmations` | 人工确认与其来源 |

### 4.2 统一明细结构

| 字段 | 含义 |
| --- | --- |
| `record_id` | 稳定来源标识；B 方向记录另带 `b_row_id` |
| `source` | 文件标识、工作表标识、原始行号及相关单元格位置 |
| `raw_fields` | 原始值、类型、公式及来源引用 |
| `normalized_fields` | 完整日期、检索名称、数量、单价、金额等 |
| `context` | 所属日期组、单据组、原始备注及必要上下文 |
| `direction` | `in`、`out` 或 `unknown` |
| `issues` | 缺失、解析异常和待确认原因 |

十进制数值在结构化交接中使用字符串表达，由程序使用十进制运算。空值与零值分开，不把无法解析的数字变成零，不对源值统一保留两位小数。写回 Excel 时保持来源数值和可核查的数值类型。

原公式与计算结果分开保存。明细金额公式优先承接已计算结果；公式缓存缺失或可信性不足时，需要受支持的重算能力或人工确认，不能把公式文本当金额、把空缓存当零或交给模型心算。

### 4.3 准备结果 `PreparedData`

```text
PreparedData
  task_context
  source_snapshot_ref
  table_profiles_ref
  a_records_ref
  b_records_ref
  c_baseline_ref
  a_baseline_totals
  preparation_issues_ref
  readiness
```

`readiness` 为 `ready / needs_input / failed`。只有已具备明确字段、期间和可用业务数值的数据包才能进入正式匹配；可逐行处理的业务异常保留在 `issues`，由第二块形成相应结果。

B 查询索引可重建，由标准化记录和规则版本决定。所有引用必须对应同一任务和数据版本。

## 5. 建议工具边界与异常处理

建议提供接收文件、解析工作簿、提取结构摘要、验证字段映射、创建 C 底稿、标准化记录及建立 B 索引等程序工具。工具返回结构化结果、错误码和来源位置，具体函数名在实现时确定。

文件损坏、必要字段未确定、无法解析的任务期间或关键公式结果缺失，需形成明确失败或待确认原因。用户补充后从对应阶段恢复；映射或来源数据变化会生成新版本，旧匹配和产物不能继续沿用。

## 6. 本块完成标准

- 原文件和 C 底稿独立，工作簿内容完整保留。
- A 明细顺序、字段映射和原始位置明确，标题及合计不混入业务列表。
- 合并日期正确补全，格式与任务月份一致，无跨分组误填。
- A 原始数量、单价、金额保持原值，超过两位小数的数值可精确追溯。
- B 入库、出库、零金额及异常行均有记录身份和去向入口。
- 明细金额公式有可核查的计算结果或明确阻塞原因。
- 模型建议经过程序验证，必要人工确认可保存并续跑。
- `PreparedData` 可独立载入，第二块无需重新推测文件角色和字段含义。

## 7. 首版实现对应

后端代码位于 `backend/app/preparation/`，分为领域契约、应用用例、LangGraph 编排及基础设施四层，上传和续跑接口单独放在 API 层。

当前已提供 `.xlsx` 接入、可选人工参考表、完整来源快照、表头规则及可选模型识别、字段校验、标准化明细、A/C 底稿、B 查询索引、审计、版本管理和持久化中断恢复。第一块的 `ready` 仅代表准备完成，不代表最终对账完成。

现阶段不内置 `.xls`/CSV 保真转换及公式重算引擎；不支持的格式明确拒绝，缺少必要公式结果时等待人工补充。底稿清理静态填充，条件格式及表格样式在第三块的最终显示处理与验收中继续落实。

运行方式、接口、交接产物和验证命令见 [后端实现说明](../../backend/README.md)。
